La version 9.0.0 de [Cecil](https://cecil.app) est sortie et apporte notamment une réponse à un besoin très concret : pouvoir organiser un site avec des sections imbriquées.

<!-- break -->

## Un besoin récurrent

Jusqu’à maintenant Cecil proposait un système de « Sections » permettant de regrouper des pages autour d’un même sujet : une documentation, des produits, des projets ou encore des articles.

Néanmoins, en pratique cette organisation ne s’arrête pas toujours à un seul niveau. Une documentation peut contenir une sous-section « Guides », elle-même organisée en plusieurs thèmes. Même chose pour un catalogue qui regroupe des produits par famille puis par sous-famille.

On veut alors conserver une structure lisible dans les fichiers :

```text
pages/
└── documentation/
    ├── index.md
    └── guides/
        ├── index.md
        └── cecil/
            ├── index.md
            └── premier-site.md
```

> Cette arborescence décrit naturellement le contenu. Elle évite de créer une convention parallèle uniquement pour représenter la hiérarchie dans les templates.

## Une réponse pragmatique

Avec Cecil 9.0.0, les sections peuvent être imbriquées : une section n’est plus obligée d’être un niveau racine de l’arborescence.

L’intérêt est moins d’ajouter une nouvelle couche d’abstraction que de laisser l’organisation du contenu faire son travail. Les dossiers restent des dossiers, les pages restent des fichiers Markdown et la hiérarchie reste visible directement dans le projet.

## Des templates lisibles

Cette organisation est également utile au moment de construire les pages de navigation. Un template peut continuer à parcourir les pages et les sections fournies par Cecil, sans devoir reconstituer toute la hiérarchie à partir de chemins de fichiers.

Par exemple, une page d’index peut simplement afficher les pages de sa section :

```twig
{% for page in page.pages %}
  <a href="{{ page.url }}">{{ page.title }}</a>
{% endfor %}
```

Le détail de la navigation dépend bien sûr du template utilisé, mais le principe reste le même : le contenu exprime sa structure et le rendu l’utilise.

## Simple mais pas limité

Dans le cas des sections imbriquées, l’approche retenue a plusieurs avantages :

- la structure est immédiatement compréhensible dans Git ;
- l’ajout d’un niveau ne demande pas de mécanisme spécial ;
- les contenus restent écrits en Markdown ;
- les templates peuvent s’appuyer sur la hiérarchie existante ;
- le comportement reste compatible avec une organisation plus plate.

Il n’est donc pas nécessaire de repenser un site existant pour profiter de cette évolution. Une arborescence à un seul niveau continue de fonctionner ; on peut introduire des sous-sections seulement lorsque le contenu le justifie.

## Mise à jour

Pour essayer cette nouvelle version, il suffit de [mettre à jour Cecil](https://cecil.app/fr/telecharger/#update) puis de reconstruire le site.

Comme toujours, je conseille de vérifier le résultat avec le contenu et les templates du projet, en particulier si la navigation dépend fortement de la structure des sections.
